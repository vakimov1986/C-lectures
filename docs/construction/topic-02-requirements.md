# Тема 2. Вимоги до програмного забезпечення

## Про що ця тема

**Вимоги** описують, що повинна забезпечувати майбутня система та яким умовам вона має відповідати. Перед початком реалізації важливо з’ясувати потреби замовника, поставити уточнювальні запитання та погодити обмеження.

Варто розрізняти **функціональні вимоги**, що визначають можливості системи, і **нефункціональні вимоги**, що описують характеристики її роботи, наприклад продуктивність або надійність.

**User Story (користувацька історія)** допомагає сформулювати потребу з погляду конкретного користувача. Її потрібно доповнювати критеріями приймання, за якими можна перевірити виконання очікуваного результату.

## Заняття за навчальним графіком

- **Л-4.** Вимоги до програмного забезпечення — 2 год.
- **СР-4.** Приклади функціональних та нефункціональних вимог — 2 год.
- **Л-5.** Користувацькі історії (User Stories) — 2 год.
- **СР-5.** Створити набір User Stories для простої системи — 2 год.
- **ЛР-1.** Аналіз та формування User Stories — 2 год.
- **СР-6.** Підготувати User Stories для практичної роботи — 2 год.

## Орієнтири для опрацювання

Потрібно вміти відрізняти вимогу від проєктного рішення, формулювати користувацькі історії, ставити уточнювальні запитання та визначати критерії приймання.

**Опорний матеріал:** *Object-Oriented Design*, с. 8–16, — основи визначення вимог, компроміси та характеристики якості. Методики створення User Stories і критерії приймання необхідно вивчати за іншими джерелами.
