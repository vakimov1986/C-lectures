# Тема 6. Якість програмного коду та рефакторинг

## Про що ця тема

Якість коду залежить не лише від того, чи програма працює правильно. Важливо також, наскільки легко іншим розробникам зрозуміти й змінити її реалізацію.

**Зрозумілі назви** класів, методів і змінних мають передавати їхнє призначення. Принцип **KISS (Keep It Simple, Stupid)** нагадує, що рішення не варто ускладнювати без потреби. Принцип **DRY (Don't Repeat Yourself)** допомагає помічати дублювання знань і логіки.

**Рефакторинг** — це вдосконалення внутрішньої структури коду без навмисної зміни його зовнішньої поведінки. Перед змінами потрібно мати спосіб перевірити, що програма працює так само, як раніше.

## Орієнтири для опрацювання

Потрібно вміти знаходити незрозумілі назви, дублювання й зайву складність; пропонувати невеликі безпечні покращення та пояснювати, як перевірити збереження поведінки програми.

**Обмеження джерела:** *Object-Oriented Design* пояснює загальні принципи підтримуваності й розмежування відповідальностей (с. 57–70), але **не навчає безпосередньо іменування, KISS, DRY чи технік рефакторингу**. Цей матеріал необхідно розробити окремо, з прикладами C#.
